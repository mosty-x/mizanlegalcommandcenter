## تحديث 1.1.0 — مزود SSH Gateway

من الإعداد والتخصيص تقدر تضيف سيرفر SSH ينفذ المهمة كاملة. بيانات الدخول مشفرة، وبصمة المضيف إلزامية، والاختبار يتحقق من مستقبل المهمة. راجع [دليل الربط](public/ssh-gateway-guide.md) لتثبيت مستقبل السيرفر وضبط `ALLOWED_SSH_HOSTS`. مجلد `ssh-server` مخصص للسيرفر البعيد، وليس لتشغيله داخل Railway.

الترقية تحافظ على قاعدة البيانات والخزنة الحالية. لا تغيّر مفاتيح التشفير أو الـ Volume. لو عندك سياسة مزودات محفوظة، حدّثها لتسمح بـ `ssh-gateway` واسم ملف التشغيل.

المزودات المباشرة تستخدم تحليلًا واحدًا بمنهج متخصص لكل أداة. مزود SSH يفوض التنفيذ إلى برنامج السيرفر وفق عقد موحد؛ المعالج المرجعي المرفق ينقل نفس التحليل إلى السيرفر. لا توجد منظومة وكلاء متعددة المراحل ضمن هذه الإضافة.

التحقق المحلي: `npm test` لاختبارات النقل والحالات السلبية، ثم `npm run build` و`npm run smoke` لاختبار نسخة الإنتاج عبر خادم SSH محلي ونتائج اصطناعية. هذه الاختبارات لا تثبت جودة التحليل القانوني أو جاهزية سيرفرك الفعلي.

منصة قانونية عربية تضم خمسة مسارات عمل فعلية: النفاذ القانوني، النزاعات والتحكيم، غرفة الصفقة، المسار التنظيمي، وقيادة ملف العميل. هذه الحزمة مبنية من مصدر المنصة الأصلية وتحافظ على رفع المستندات، مزودي الذكاء، ملفات تخصيص المكتب، سجل المصادر، شفافية النتيجة، والاعتماد البشري.

## ما تغير في نسخة Railway

- تشغيل قياسي عبر Next.js داخل Docker.
- قاعدة SQLite دائمة وملفات مشفّرة داخل Railway Volume.
- جلسة متصفح موقعة داخل Cookie أساسي من نوع HttpOnly.
- أول زيارة تعرض دليل المسارات الخمسة وشروط الاستخدام.
- لا تُفتح مساحة العمل قبل مراجعة المسارات وقبول الشروط.
- المستخدم العائد يتجاوز الدليل طالما أن Cookie موجود وقبول نفس نسخة الشروط محفوظ على الخادم.
- عند تغيير `TERMS_VERSION` يظهر الدليل والشروط لكل المستخدمين مرة أخرى.

## النشر على Railway

1. فك الضغط وارفع محتويات المجلد إلى مستودع GitHub جديد.
2. في Railway أنشئ مشروعًا من المستودع. سيكتشف `railway.json` و`Dockerfile` تلقائيًا.
3. أضف Volume واربطه بالمسار:

   `/data`

4. أضف المتغيرات التالية في Variables:

   - `DATA_DIR=/data/mizan`
   - `CREDENTIAL_MASTER_KEY` مفتاح Base64 بطول 32 بايت.
   - `SESSION_SIGNING_KEY` مفتاح Base64 مختلف بطول 32 بايت.
   - `TERMS_VERSION=2026-09-04`
   - `ALLOWED_AI_HOSTS` اختياري، ويقبل نطاقات إضافية مفصولة بفاصلة.

5. أنشئ المفتاحين محليًا في PowerShell، وشغّل الأمر مرتين:

```powershell
[Convert]::ToBase64String([Security.Cryptography.RandomNumberGenerator]::GetBytes(32))
```

6. اضغط Deploy ثم Generate Domain. فحص Railway يستخدم `/api/health` ولن يعتبر النسخة جاهزة إذا كانت المفاتيح ناقصة أو غير صحيحة.

## سلوك أول زيارة

المسار `/api/onboarding` ينشئ معرفًا عشوائيًا غير مشتق من البريد أو الجهاز، يوقّعه بمفتاح الخادم، ثم يحفظه في Cookie آمن. قاعدة البيانات تحفظ وقت أول وآخر زيارة، عدد الزيارات، وقت إنهاء الدليل، نسخة الشروط، ووقت قبولها. لا توجد Cookies إعلانية أو بصمة جهاز.

الحد الصريح: بدون نظام حسابات، التذكر مرتبط بنفس المتصفح والجهاز. حذف Cookie أو فتح الموقع من جهاز جديد يعامل الزيارة كأول مرة. هذا مقصود حتى لا نجمع بيانات شخصية غير مطلوبة.

## التخزين والأمان

- مفاتيح مزودي الذكاء والمستندات والمخرجات وملفات التخصيص مشفرة باستخدام AES-256-GCM.
- مفتاح التشفير لا يُكتب في المستودع أو قاعدة البيانات.
- كل سجل مربوط بمعرف الجلسة، والاستعلامات لا ترجع بيانات جلسة أخرى.
- روابط مزودي الذكاء مقيدة بـ HTTPS وقائمة نطاقات مسموحة لمقاومة SSRF.
- المخرجات تُراجع ضد معرفات المصادر، وتفصل المراجع الصحيحة عن المراجع التي اخترعها الموديل.
- لا يتم تنفيذ أي مخرجات من الموديل ككود أو أمر نظام.
- رؤوس CSP وHSTS ومنع الإطارات وتقييد صلاحيات المتصفح مفعلة.
- التشغيل مصمم لخدمة Railway واحدة متصلة بـ Volume واحد. لا تشغل عدة Replicas على ملف SQLite نفسه.

## التشغيل المحلي

يتطلب Node.js 24 أو أحدث.

```bash
npm ci
cp .env.example .env.local
npm run dev
```

استبدل القيمتين الوهميتين في `.env.local` بمفتاحين حقيقيين قبل فتح المنصة.

## المسارات المهمة

- `/` لوحة القيادة.
- `/tools/enforceability` النفاذ القانوني.
- `/tools/disputes` النزاعات والتحكيم.
- `/tools/deal-room` غرفة الصفقة.
- `/tools/regulatory` المسار التنظيمي.
- `/tools/client-command` قيادة ملف العميل.
- `/settings` مزودات الذكاء وملفات تخصيص المكتب.
- `/api/health` جاهزية الخادم والتخزين والمفاتيح.

## تغيير الشروط

عدّل نص الشروط داخل `components/onboarding-gate.tsx` ثم غيّر قيمة `TERMS_VERSION` في Railway. الزيارات التي وافقت على الإصدار القديم ستُطلب منها مراجعة الإصدار الجديد وقبوله.
