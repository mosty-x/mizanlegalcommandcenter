# ربط سيرفر تنفيذ بميزان — الإصدار 1.1.0

في الإعداد والتخصيص اختار `SSH Gateway`، واحفظ العنوان والمنفذ والمستخدم والمفتاح الخاص وكلمة سر المفتاح (إن وجدت) وبصمة السيرفر. خانة ملف التشغيل هي اسم profile متفق عليه مع برنامج السيرفر، وليست مسار ملف أو أمر شِل. المثال: `legal-default`.

في استضافة Railway أضف متغيّرًا يحدد بالضبط السيرفرات المسموحة:

```env
ALLOWED_SSH_HOSTS=server.example.com:22
```

استخدم فاصلة لإضافة أكثر من سيرفر. لا تضع مفاتيح SSH في هذا المتغير أو المستودع. الاتصال صادر مباشرة من Backend Railway إلى السيرفر؛ لا تحتاج Relay إضافيًا لهذه النسخة. السماح بعنوان داخلي يمنح التطبيق وصولًا إليه؛ اسمح فقط بسيرفر تملكه وتثق فيه. العميل الحالي يتصل عبر IPv4.

## جهّز السيرفر مرة واحدة

المفاتيح تتيح الدخول فقط. لازم يكون فيه محرك تنفيذ أو برنامج استقبال على السيرفر. لو عندك محرك بالفعل، استخدم عقد الاتصال أدناه. ولو محتاج نقطة بداية، الحزمة فيها مجلد `ssh-server` يحتوي مستقبلًا فعليًا ومعالجًا مرجعيًا لخدمة متوافقة مع OpenAI (مثل خدمة محلية موجودة عندك). المعالج المرجعي ينفذ نفس طلب التحليل الموجود في النسخة الأصلية، ولا يمثل خمس منظومات وكلاء متعددة المراحل.

على Linux مع Node.js 24، وبعد نقل مجلد `ssh-server` إليه:

```bash
sudo install -d -m 755 /opt/mizan
sudo install -d -m 750 -o root -g mizan /etc/mizan
sudo install -m 755 ssh-server/mizan-workflow.mjs /usr/local/bin/mizan-workflow
sudo install -m 644 ssh-server/openai-compatible-handler.mjs /opt/mizan/openai-compatible-handler.mjs
sudo install -m 640 -o root -g mizan ssh-server/receiver.example.json /etc/mizan/receiver.json
sudoedit /etc/mizan/receiver.json
```

هذه الأوامر تفترض وجود مستخدم ومجموعة `mizan` للدخول. عدّل أسماءهما لو بتستخدم حسابًا مختلفًا. في ملف الإعداد ضع اسم الموديل الموجود فعليًا ورابط خدمته ومفتاحها إذا احتاجت. أسرار خدمة الذكاء تبقى على السيرفر. لتوصيل محركك الخاص غيّر `handler` إلى مسار module مطلق يصدّر `health(config)` و`run(packet, config)`؛ الكود لازم يرجع النتيجة بدل طباعتها. سجلات stdout تفسد البروتوكول. لا تجعل المسار أو الخدمة تابعين لقيم قادمة من المستندات.

استخرج بصمة المضيف من شاشة السيرفر الموثوقة:

```bash
sudo ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub -E sha256
```

انسخ قيمة `SHA256:...` فقط. لو السيرفر عنده أكثر من نوع مفتاح، البصمة لازم تخص المفتاح المتفاوض عليه. يفضل تخصيص هذا الحساب وتقييد مفتاحه في `authorized_keys`:

```text
restrict,command="/usr/local/bin/mizan-workflow --stdio" ssh-ed25519 YOUR_PUBLIC_KEY
```

لا تستخدم المفتاح الخاص في `authorized_keys`. افتح منفذ SSH في جدار الحماية للاتصالات المصرح بها. جرّب زر «اختبار»: نجاحه يثبت تسجيل الدخول وبصمة المضيف وجاهزية المستقبل؛ المعالج المرجعي لا ينفذ استدلالًا مدفوعًا خلال اختبار الجاهزية. أول تشغيل هو اختبار خدمة الذكاء الفعلي.

## عقد الاتصال بمحركك الخاص

الأمر ثابت: `/usr/local/bin/mizan-workflow --stdio`. لا shell تفاعلي أو نقل agent أو أوامر قادمة من الواجهة. يتم إرسال JSON واحد عبر stdin حتى EOF، والرد JSON واحد عبر stdout ثم exit code 0.

طلب فحص الجاهزية:

```json
{"protocol":"mizan.workflow.v1","requestId":"UUID","operation":"health"}
```

رد الجاهزية:

```json
{"protocol":"mizan.workflow.v1","requestId":"SAME_UUID","ok":true,"ready":true}
```

طلب التشغيل يحتوي:

- `protocol`, `requestId`, `operation: "run"`.
- `workflow`: النسخة، `toolSlug`، `profile`، العنوان، الهدف، الاختصاص.
- `documents`: الملفات الأصلية كـ Base64 مع الاسم والنوع والمعرف والحجم وبصمة SHA256؛ حتى 8 ملفات بحد 10 MiB للملف.
- `sources`: مقتطفات النص ومعرف كل مقتطف ومستنده وصفحته؛ الحد الحالي 140 ألف حرف أو 42 مقتطفًا، و`sourceTruncated` يعلن الاختصار. لا تستخدم اسم الملف كمسار كتابة.
- `customization`: ملفات إعداد المكتب المحفوظة. لا تتضمن مفاتيح المزودات.
- `prompt`: تعليمات التحليل المتخصصة لكل أداة وهيكل النتيجة. يمكنك تنفيذ منهجك الخاص مع احترام العقد والسياسات.
- `policy`: مراجعة بشرية مطلوبة، ولا إرسال أو إيداع أو إجراء خارجي تلقائي.

رد التشغيل:

```json
{
  "protocol": "mizan.workflow.v1",
  "requestId": "SAME_UUID",
  "ok": true,
  "output": {
    "title": "عنوان النتيجة",
    "executiveSummary": "الملخص",
    "findings": [{"title":"ملاحظة","category":"وقائع","severity":"معلومة","explanation":"الشرح","recommendation":"المقترح","sourceRefs":["SOURCE_ID_FROM_PACKET"],"confidence":70}],
    "missingInformation": [], "recommendedActions": [], "assumptions": [],
    "humanDecisionRequired": ["مراجعة المحامي"],
    "disclaimer": "تحليل مساعد يحتاج مراجعة محامٍ."
  },
  "usage": {"inputTokens": null, "outputTokens": null}
}
```

درجات المخاطر: منخفض، متوسط، مرتفع، حرج، معلومة. ارجع المصادر من معرفات `sources` فقط. المنصة تتحقق من انتماء المرجع للمقتطفات المرسلة؛ ده لا يثبت صحة الاستنتاج أو إن النص يؤيده. لا تنفذ تعليمات مستند أو مخرج نموذج كأوامر. المعالج البعيد جزء موثوق ومسؤول عن ضبط أدواته وصلاحياته واحتفاظه بالبيانات.

المهلة 90 ثانية، الرد 1.5 MB، طلب واحد متزامن لكل سيرفر وأربعة اتصالات على نسخة التطبيق. لا إعادة إرسال تلقائية: لو الاتصال اتقطع قد تكون المهمة البعيدة بدأت، وقطع الاتصال لا يضمن إلغاء أدوات محرك خارجي. استخدم `requestId` لتتبع الطلب ومنع تكراره داخل محركك. الوظائف الطويلة تحتاج بروتوكول مهام غير متزامن لاحقًا؛ هذه النسخة تطلب ردًا نهائيًا داخل المهلة.

## ترقية النسخة

ارفع المصدر الجديد إلى مستودع الاستضافة وأعد النشر، مع الاحتفاظ بالـ Volume و`CREDENTIAL_MASTER_KEY` و`SESSION_SIGNING_KEY` الحاليين. لا يوجد تعديل لجدول البيانات؛ حزمة SSH مشفرة في خانة الأسرار الحالية. المزودات القديمة تعمل كما هي. لو رفعت سياسة مزودات قديمة، أضف `ssh-gateway` في `allowedProviders` وأضف اسم ملف تشغيلك إلى `approvedModels` عندما تكون القائمة محددة. القالب الجديد لا يغير السياسات المحفوظة تلقائيًا.

تنبيه التشغيل المشترك: نسخة 1.0 تعتمد على كوكي متصفح موقعة لعزل المساحة، ولا تحتوي حسابات دخول أو أدوار فريق. مسح الكوكي يفقد الوصول إلى المساحة السابقة. هذه الإضافة لا تستبدل ذلك بنظام حسابات؛ يلزم التحكم في وصول المستخدمين قبل إتاحة رفع مفاتيح حقيقية على موقع عام.
